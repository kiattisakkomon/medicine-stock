# Medicine Stock — วิธีติดตั้ง (Supabase + GitHub Pages)

## ภายในชุดไฟล์
- `schema.sql` — ตารางยา ล็อต ธุรกรรม ตรวจนับ, RLS, SQL functions
- `index.html`, `style.css`, `app.js` — เว็บแอปภาษาไทย
- `config.js` — ใส่ Supabase Project URL และ Publishable Key

## 1. สร้างฐานข้อมูล
1. เปิด Supabase Dashboard ของโปรเจกต์ที่สร้างแล้ว
2. คลิก **SQL Editor** (ไอคอน `>_` แถบซ้าย) → **New query**
3. เปิด `schema.sql` คัดลอกทั้งหมด วางในช่อง SQL → กด **Run**
4. ไปที่ **Table Editor** จะพบ `medicines`, `lots`, `transactions`, `stock_counts`

**ข้อควรระวัง:** SQL นี้เหมาะสำหรับโปรเจกต์ใหม่ที่ยังไม่มีตารางชื่อเดียวกัน หากมีข้อมูลเดิมอยู่ ให้สำรองข้อมูลก่อน ไม่ควรรัน SQL แบบไม่ตรวจสอบการชนของโครงสร้าง

## 2. สร้างบัญชีผู้ใช้
1. ไปที่ **Authentication → Users** → **Add user** → **Create new user**
2. ระบุอีเมลและรหัสผ่านของผู้ใช้งาน (ถ้ามีตัวเลือก Auto Confirm ให้ยืนยันอีเมล)
3. ผู้ใช้สามารถล็อกอินในหน้าเว็บด้วยบัญชีนี้
4. เพื่อจำกัดการสมัครจากบุคคลภายนอก แนะนำไปที่ Authentication → Providers → Email แล้วปิด **Allow new users to sign up** (ชื่อเมนูอาจต่างตาม UI)

## 3. เชื่อมเว็บแอปกับ Supabase
1. ไปที่ **Project Settings → API Keys** และหน้า **Data API** (หรือ Connect) เพื่อดู Project URL
2. เปิดไฟล์ `config.js` ด้วย Notepad / VS Code
3. แก้ `supabaseUrl` เป็น URL ของโปรเจกต์ (รูปแบบ `https://xxxx.supabase.co`)
4. แก้ `supabaseKey` เป็น **Publishable key** (หรือ legacy **anon public key**)
5. บันทึกไฟล์

**ห้ามใส่ `service_role`, `sb_secret_...`, รหัสผ่านฐานข้อมูล หรือ JWT secret ลงใน `config.js`** เพราะไฟล์นี้ถูกเผยแพร่ให้เบราว์เซอร์อ่านได้

## 4. ทดสอบเว็บแอป
- เปิด `index.html` ผ่านเว็บเซิร์ฟเวอร์ เช่น VS Code Live Server หรือใช้ `python -m http.server 8000` ในโฟลเดอร์นี้ แล้วเข้า `http://localhost:8000`
- เข้าสู่ระบบ → เพิ่มรายการยา → เพิ่มล็อต → รับยาเข้า → เบิกยาออก → ตรวจนับ → อนุมัติปรับยอด
- **อย่าเปิดไฟล์ด้วย `file://`** หากเบราว์เซอร์บล็อกการโหลดไฟล์หรือ API ให้ใช้ Live Server

## 5. เผยแพร่หน้าเว็บฟรี (GitHub Pages)
> Supabase ให้ฐานข้อมูลและ API แต่ **ไม่ได้เป็นเว็บโฮสต์ไฟล์ HTML ของชุดนี้** ต้องใช้ GitHub Pages เพื่อเปิดหน้าเว็บสาธารณะ

1. สมัคร/ล็อกอินที่ https://github.com
2. สร้าง Repository ใหม่ เช่น `medicine-stock` (เลือก Public สำหรับ GitHub Pages ฟรี)
3. อัปโหลด `index.html`, `style.css`, `app.js`, `config.js` ไปที่ **root** ของ repository (ไม่ต้องอัปโหลด `schema.sql`)
4. ไปที่ **Settings → Pages → Build and deployment** → Source: **Deploy from a branch** → Branch: **main**, Folder: **/(root)** → **Save**
5. รอให้ Pages เผยแพร่ แล้วเปิด URL ที่ GitHub แจ้ง เช่น `https://YOUR-USERNAME.github.io/medicine-stock/`
6. ล็อกอินด้วยบัญชีที่สร้างใน Supabase

**คำเตือนความเป็นส่วนตัว:** GitHub Pages ของ repository แบบ Public ทำให้โค้ดฝั่งเว็บและ Publishable Key ถูกมองเห็นได้ (เป็นการออกแบบปกติ) แต่ข้อมูลฐานข้อมูลต้องได้รับการป้องกันด้วย RLS และการล็อกอิน อย่าอัปโหลดข้อมูลคนไข้หรือข้อมูลส่วนบุคคลที่อ่อนไหวลงในระบบตัวอย่างนี้ก่อนผ่านการประเมินความปลอดภัยและสิทธิ์ผู้ใช้

## 6. แจ้งเตือนวันหมดอายุ
- หน้า **ใกล้หมดอายุ** แสดงล็อตที่หมดอายุแล้ว หรือจะหมดอายุใน 30 วัน และยังมีสต็อก
- กด **ส่งออก CSV** เพื่อบันทึกรายงาน หรือ **เปิดอีเมลเพื่อส่งรายงาน** เพื่อส่งเอง
- **ชุดเริ่มต้นนี้ยังไม่ส่งอีเมลอัตโนมัติ 08:00 น.** การทำงานแบบไม่ต้องเปิดเว็บต้องเพิ่ม Scheduled Job (เช่น Supabase Cron + Edge Function + ผู้ให้บริการส่งอีเมล) และตรวจสอบโควตา/การเปิดใช้งานตามแพ็กเกจ

## ข้อจำกัดและแนวทางก่อนใช้งานจริง
- RLS ตัวอย่างนี้ให้ **ผู้ใช้ที่ล็อกอินทุกคน** อ่านข้อมูลและเพิ่มยา/ล็อต/บันทึกธุรกรรม/อนุมัติการปรับยอดได้ ยังไม่มีสิทธิ์แยก Admin/Staff และยังไม่เหมาะกับข้อมูลทางการแพทย์ส่วนบุคคล
- การแก้ไข/ลบธุรกรรมไม่ได้เปิดให้ทำจากหน้าเว็บ เพื่อคงประวัติการเคลื่อนไหว
- จำนวนคงเหลือคำนวณจากธุรกรรมทั้งหมด (ไม่ควรแก้ตาราง `transactions` โดยตรง)
- ฟังก์ชันตรวจนับจะไม่อนุมัติถ้ายอดสต็อกเปลี่ยนระหว่างตรวจนับกับอนุมัติ ต้องตรวจนับใหม่
- จำนวนหน่วยรวมบน Dashboard อาจเป็นคนละหน่วยนับกัน ใช้เพื่อภาพรวมเท่านั้น
- ประวัติธุรกรรมในหน้าจอจำกัด 1,000 รายการล่าสุด
- หากฐานข้อมูล/โปรเจกต์ฟรีถูกพักเพราะไม่มีการใช้งาน ให้เปิด Supabase Dashboard เพื่อดำเนินการตามข้อความแจ้งเตือนของผู้ให้บริการ

## ทดสอบตัวอย่าง
1. เพิ่มยา `PARA500` / `Paracetamol 500 mg`
2. เพิ่มล็อต `LOT001` วันหมดอายุอีก 20 วัน
3. รับเข้า 100 → เบิกออก 20 → คงเหลือ 80
4. ตรวจนับ 75 → อนุมัติ → ระบบสร้าง `ADJUST_OUT` จำนวน 5 → คงเหลือ 75
5. ตรวจสอบหน้าหมดอายุ จะพบล็อตนี้
